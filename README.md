# Horizon Manager 0.1.6

Horizon Manager устанавливает оригинальный Horizon на VPS и управляет им через нативное Android-приложение. Язык интерфейса и выпуска выбирается по языку Android. Доступны английский, русский и упрощённый китайский. Внизу три раздела: «Архив», «Лента» и «Настройки». «Лента» показывает последний готовый выпуск в пределах окна сбора, «Архив» — выпуски старше этого окна. Например, при окне 12 часов отсчёт составляет 12 часов с момента готовности выпуска. Источники, управление, серверы и журнал открываются из настроек. Поиск и фильтры ленты доступны по значкам в её шапке. Сортировка по времени загружает весь выпуск и показывает сначала самые старые новости.

В «Настройки → Тема» можно выбрать «Океан», «Графит», «Нефрит», «Аметист» или «Янтарь». Тема настраивает фон, акценты, ссылки и оттенки светлого текста. Выбор сохраняется на телефоне.

В карточке актуального дайджеста значки синхронизации, полного выпуска и архива находятся справа от заголовка. Досрочный перенос действует на этом телефоне для выбранного профиля VPS. Лента затем покажет следующий выпуск в пределах окна сбора, если он есть. Пока VPS формирует новый дайджест, в ленте виден индикатор подготовки.

«Лента» и открытый выпуск в «Архиве» используют одни и те же карточки, поиск, фильтры, сортировку и просмотр полного дайджеста. Настройки сгруппированы по выпуску, приложению и серверу. Окно сбора, квоты и группировка редактируются вместе в «Настройки дайджеста». Журнал, инструменты агента и резервные копии находятся в «Обслуживании».

Готовый APK доступен на странице [релиза 0.1.6](https://github.com/DEGSOL/HorizonManager/releases/tag/v0.1.6). Приложение устанавливается поверх 0.1.5 с сохранением локальных данных. Если вы переходите с 0.1.4, приложение устанавливается рядом с ним. Подключите существующий агент в настройках VPS, чтобы открыть прежние дайджесты.

Версия 0.1.6 работает с агентом 0.1.3. Если на VPS установлена более ранняя версия, откройте «Настройки → Обслуживание → Обновить агент на VPS». Обновление сохраняет серверную базу, архив и расписание. При сбое обновления установщик пытается вернуть предыдущие файлы и запустить прежнюю службу. Результаты локальных проверок и проверки, которые ещё требуют телефона или отдельного VPS, перечислены в [docs/VERIFICATION.md](docs/VERIFICATION.md).

## Первый запуск с телефона

1. Установите APK на Android 8.0 или новее. Понадобится ваш VPS с Ubuntu Server 24.04 LTS либо Debian 12, systemd, SSH и доступом к репозиториям ОС, GitHub и PyPI. Установщик проверяет архитектуру, минимум 432 МиБ RAM по MemTotal и 1,5 ГиБ свободного диска. Рабочее потребление зависит от выбранных источников и объёма обработки. Для длительной эксплуатации оставьте запас RAM и диска.
2. Введите данные SSH. Можно выбрать файл приватного ключа через системный проводник. При первом подключении сверьте отпечаток SSH с доверенным источником, например панелью провайдера VPS. SSH-сервер должен разрешать локальную переадресацию до `127.0.0.1:18777`.
3. Просмотрите отчёт и подтвердите установку. При необходимости укажите пароль sudo. Установка подготавливает недостающие пакеты и включает службу Horizon Manager. Телефон может отключиться после создания серверного задания. После возвращения приложение загрузит состояние по SSH.
4. В разделе «Настройки» откройте «Модель AI». Укажите провайдера и точный идентификатор модели. Сохраните. Введите API-ключ в настройках AI и сохраните. Смена телефона и переустановка Android-клиента не стирают ключ в базе агента. «Проверить сохранённую модель» делает небольшой реальный запрос. Результат виден в истории заданий и журнале.
   Для OpenRouter и UnoRouter на том же экране введите ключ и нажмите «Подключить и загрузить модели». Выберите модель через поиск и сохраните настройки. При повторном открытии агент загружает каталог ключом из базы VPS. Android получает список моделей и имя сохранённого секрета. После переустановки Android-клиента выберите «Подключить существующий агент» в настройке VPS. Снова вводить AI-ключ при подключении к той же базе не требуется.
5. Откройте «Настройки → Источники → RSS / Atom», добавьте ленту с недавними публикациями, задайте название и URL, включите её и примените настройки. Выберите соответствующий профиль. Тест сохранённого источника позволяет проверить сбор без затрат на AI.
6. Нажмите «Запустить сбор». Следите за этапами в разделе «Настройки → Управление». Когда Horizon сформирует дайджест, в «Ленте» появятся карточки и Markdown. Если свежих публикаций нет либо все отфильтрованы, интерфейс покажет фактический результат.
7. При необходимости настройте расписание. Для ежедневной обработки выберите режим по дням недели, отметьте все дни и укажите время. По умолчанию в форме используется `Asia/Yekaterinburg`. Запуски планирует VPS даже при отключённом телефоне.

В профиле соединения HTTPS можно указать доверенный домен, на котором уже работает обратный прокси к агенту. По умолчанию API доступен внутри канала SSH. В «Настройки → Уведомления» включите «Фоновая проверка новостей» и разрешите уведомления. Если ntfy установлен, выберите «Подключить push-уведомления» и ntfy в списке служб UnifiedPush. По умолчанию агент принимает адреса доставки ntfy.sh. Для собственного сервера ntfy задайте `HM_PUSH_HOST` через systemd override агента и выберите тот же сервер в ntfy. Отдельный публичный адрес для Horizon Manager при этом не требуется.

При push телефон получает только подписанный идентификатор нового выпуска. Без подключённого push Android планирует сетевую проверку с интервалом 30 минут, а при активном push сверяет выпуски раз в шесть часов. Точное время фоновых проверок выбирает Android. После нажатия на уведомление приложение открывает ленту указанного VPS.

Новые выпуски формируются на трёх языках, поэтому обогащение статей может стоить больше запросов к AI. Если в старом выпуске нет языка телефона, откройте его в архиве и нажмите «Перевести выпуск». Операция использует сохранённые материалы и текущего AI-провайдера.

### Данные и резервная копия

Экспорт в разделе «Настройки → Обслуживание → Резервные копии и перенос» сохраняет конфигурацию Horizon, профили, секреты и расписание. Для расшифровки нужен пароль резервной копии. Архив новостей и историю событий эта копия не содержит. Перед импортом или обновлением системы можно сделать снимок диска средствами VPS. Профили, экспортированные отдельно, представлены в формате Manager с отдельными полями текстов промптов.

При обнаружении существующего Horizon приложение показывает его путь или соответствующий контейнер. Можно скопировать читаемый `data/config.json` через «Настройки → Обслуживание → Резервные копии и перенос». Для интеграций в новом экземпляре отдельно потребуются секреты и, при необходимости, пользовательские профили.

## Сборка Android

Откройте папку `android` в Android Studio либо используйте Gradle Wrapper. Нужны полный JDK 17 или 21 и Android SDK с `platforms;android-36` и `build-tools;36.0.0`. SDK указывается через `ANDROID_HOME` или `android/local.properties`. Wrapper фиксирует Gradle 8.13 и SHA-256 официального архива.

```bash
cd android
./gradlew :app:assembleRelease :app:testReleaseUnitTest :app:lintRelease
```

Путь подписанного результата — `android/app/build/outputs/apk/release/app-release.apk`. Перед сборкой задайте `HM_RELEASE_KEYSTORE`, `HM_RELEASE_KEY_ALIAS`, `HM_RELEASE_STORE_PASSWORD` и `HM_RELEASE_KEY_PASSWORD` в своём защищённом окружении. Сборка без этих переменных выдаёт неподписанный APK. Для обновления поверх установленной версии нужен тот же сертификат. В среде с ограниченной памятью можно добавить `--max-workers=1 -Pkotlin.compiler.execution.strategy=in-process`.

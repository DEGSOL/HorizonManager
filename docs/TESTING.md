# Тестирование

## Интеграция агента с оригинальным Horizon

Из корня проекта подготовьте отдельный checkout upstream и закреплённое виртуальное окружение.

```bash
hm_test_checkout="$(mktemp -d)"
git -C "$hm_test_checkout" init
git -C "$hm_test_checkout" fetch --depth 1 https://github.com/Thysrael/Horizon.git "$(cat bootstrap/horizon.commit)"
git -C "$hm_test_checkout" checkout --detach FETCH_HEAD
uv --directory "$hm_test_checkout" sync --frozen --no-dev --no-editable
uv pip install --python "$hm_test_checkout/.venv/bin/python" --no-deps -r agent/requirements.txt
PYTHONPATH=agent "$hm_test_checkout/.venv/bin/python" -m unittest discover -s agent/tests -v
```

Тесты запускают настоящий агент и upstream. Локальный HTTP-сервис в тестах играет роли RSS и совместимого AI API. Платный ключ и дополнительно оплачиваемый VPS для этих тестов не нужны.

## SSH-транспорт на JVM

Тесты `SshIntegrationTest` используют настоящий SSH handshake и локальный HTTP-агент через `direct-tcpip`. Подготовьте отдельное Python-окружение для `asyncssh==2.24.1` и `bcrypt==5.0.0`, чтобы оно не меняло зависимости Horizon.

1. Запустите агент на `127.0.0.1:18777` с `HM_STATE` в новом тестовом каталоге и с `CREDENTIALS_DIRECTORY`, в котором файл `api-token` содержит 64 единицы. Это известное тестовое значение разрешено исключительно в изолированном окружении.
2. Запустите `python integration/ssh_fixture.py /tmp/hm-test-key 18322` из тестового Python-окружения.
3. С теми же локальными портами выполните `HM_TEST_SSH_PORT=18322 HM_TEST_SSH_KEY=/tmp/hm-test-key ./gradlew :app:testReleaseUnitTest` из папки `android`.
4. Остановите тестовые процессы. Они слушают только loopback. При отсутствии переменных окружения Gradle помечает эти тесты пропущенными.

## Приёмка с Android на чистом VPS

Используйте временный VPS, к которому у вас есть доступ с телефона и через панель провайдера. Повторите сценарий для Ubuntu Server 24.04 и Debian 12. Указанные дистрибутивы разрешены установщиком на x86_64 и ARM64. Проверяйте архитектуры на реальных хостах.

1. Подключите VPS по паролю или ключу. Подтвердите правильный отпечаток по панели провайдера. Проверьте нештатный пароль, ключ с паролем, смену host key и обычного SSH-пользователя без sudo. 
2. Установите Manager на системе без Docker. При штатном запуске проверьте, что агент доступен с Android, а слушающий API находится на loopback. Закройте приложение на стадии загрузки зависимостей, затем откройте и проверьте восстановление статуса. 
3. На отдельном тестовом VPS воспроизведите неудачу APT или нехватку диска, верните исходное состояние и повторите установку по кнопке. После успешной установки повторный bootstrap должен сохранить конфигурацию.
4. Добавьте один доступный и один заведомо недоступный RSS. Запустите тест с неверным API-ключом, проверьте код ошибки и отсутствие секретов в экспортированном журнале. Укажите правильный ключ, понизьте порог профиля для теста при необходимости, запустите сбор и проверьте карточки и Markdown.
5. Создайте расписание, закройте Android, дождитесь серверного запуска. Перезапустите VPS в рамках тестового окна, проверьте сохранность истории, расписания, конфигурации и дайджеста. 
6. Создайте резервную копию, измените настройку, восстановите её. Проверьте отмену долгого запуска, действия на медленной сети, поиск и фильтры журнала. Для HTTPS выполните дополнительную проверку с доверенным и недоверенным TLS-сертификатом.


Для версии 0.1.2 также проверьте обновление старого агента с сохранением архива и настроек, выбор языка после переключения Android между русским, английским и китайским и раскрытие комментариев в карточке. Разрешите уведомления в Hovq и назначьте запуск на ближайшее время. Закройте приложение, заблокируйте экран и дождитесь уведомления о готовом выпуске. Повторите для ручного запуска и после перезагрузки. После обновления с 0.5.4 проверьте отсутствие служебного уведомления. Прервите подключение к VPS, восстановите его и проверьте, что уведомление о новом выпуске появилось один раз.
